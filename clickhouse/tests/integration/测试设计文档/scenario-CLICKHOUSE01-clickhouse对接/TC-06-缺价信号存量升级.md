# TC-06 缺价信号存量升级（bfe#1479）

## 用例编号与名称

TC06 缺价信号存量升级（`TestTC06PriceMissUpgrade`）

## 所属场景

CLICKHOUSE01 ClickHouse 对接（scenario-CLICKHOUSE01-clickhouse-dock）

## 版本声明

- `ai-gateway-observability`：`clickhouse/sqls/` 当前资产（明细表与 Kafka 暂存表含 `ai_price_miss` / `ai_price_warn`）
- 被测引擎：ClickHouse 26.10.1.1149（WSL2 单文件实例）
- 升级脚本：`clickhouse/sqls/upgrade/2026-10-30-issue-1479-price-miss-columns/bfe_ai_request_log_alter.sql`
- 无需 Kafka（本用例不涉及真实消费）

## 测试目的

验证存量环境的升级路径可执行且顺序正确：

1. 明细表 `ADD COLUMN IF NOT EXISTS` 可重复执行（幂等）；
2. Kafka 暂存表**不能**用 `ALTER` 加列（Kafka 存储引擎不支持任何 ALTER），必须 DROP + 按主 DDL 重建——该限制以负向断言固化；
3. 消费 MV 不重建则新列永远不落值，故重建后必须能从 `system.tables.as_select` 看到两列投影。

## 前置条件

同 TC-01（ClickHouse 可达；不要求 Kafka 可达）。

## 操作步骤

1. 按 `setup.sh` 顺序全新安装六份 SQL（含 Kafka 引擎表，不需要真实 broker）。
2. 模拟旧环境：`DROP TABLE <DB>.bfe_ai_log_load_mv`（先停消费）→ `ALTER TABLE <DB>.bfe_ai_request_log DROP COLUMN ai_price_miss, DROP COLUMN ai_price_warn`；断言两列已不存在。
3. 负向断言：`ALTER TABLE <DB>.bfe_ai_log_kafka ADD COLUMN IF NOT EXISTS it_probe Nullable(UInt8)` 必须报错且错误信息含 `not supported by storage Kafka`。
4. 升级第 2 步：`DROP TABLE <DB>.bfe_ai_log_kafka` → 按 `sqls/bfe_ai_log_kafka.sql` 重建 → 断言两列类型为 `Nullable(UInt8)` / `Nullable(String)`。
5. 升级第 3 步：执行升级脚本两次（幂等）→ 断言明细表两列就位且类型正确。
6. 升级第 4 步：按 `sqls/bfe_ai_log_load_mv.sql` 重建消费 MV → 断言 `system.tables.as_select` 含两列。

## 预期结果

- 步骤 2 后两列不存在（旧环境模拟成功）；
- 步骤 3 报 `Code: 48 ... Alter of type 'ADD_COLUMN' is not supported by storage Kafka`；
- 步骤 4 重建后的 Kafka 暂存表含两列，类型正确；
- 步骤 5 两次执行都成功（与 Doris "每环境一次"、StarRocks "不支持 IF NOT EXISTS" 的契约不同）；
- 步骤 6 重建后的 MV 投影包含 `ai_price_miss` / `ai_price_warn`。
