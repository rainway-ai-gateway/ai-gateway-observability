# TC-05 聚合表重建

## 用例编号与名称

TC-05 聚合表重建

## 所属场景

CLICKHOUSE01 ClickHouse 对接（报表存储新引擎）

## 版本声明

- `ai-gateway-observability`：当前源码版本（v0.8 ClickHouse 对接）
- `ClickHouse`：本机 WSL2 单文件 26.10.1.1149

## 测试目的

验证聚合表重建模式（DROP + CREATE 的 REPLACE 语义 + 明细重算回填）：DROP 聚合 MV 与聚合表后按仓库 DDL 重建，重建后数据为空，按设计稿 §4.3 的历史窗口重算语句（`INSERT INTO <聚合表>` + 聚合 MV 的 SELECT 主体，`GROUP BY` 全 40 维）从明细回填，口径与重建前逐项一致。ClickHouse 无 Doris `REPLACE WITH TABLE` 原子换名（HOWTO §11.3 流程为 Doris 专属），重建窗口的非原子性由「先 DROP 聚合 MV 停止增量写入」保证。

## 运行模式

单组件模式：直连真实 ClickHouse，在独立测试库中完整走一遍重建 + 重算流程。

## 前置条件

1. ClickHouse 已启动，default 无密码可连。
2. 同 TC-03 的三行样例等价数据（重建前后共用同一套断言 `assertAggregation`）。

## 测试数据构造

- 独立测试库，建明细表/聚合表/聚合 MV（不建 Kafka 表与消费 MV）。
- 三行样例等价数据（同 TC-03，插入语句只列非默认值列，空串/0/空数组由列默认值承担），落固定分钟桶 `T0`。

## 执行步骤

1. 创建独立测试库并建三类对象；写入三行样例数据；等待 1s。
2. 执行重建前口径断言（整窗 9 指标 + 5 组维度分布，同 TC-03），作为重建后比对的基线。
3. 逆序 DROP（同 cleanup.sh）：`DROP TABLE bfe_ai_metrics_1m_mv`（ClickHouse 中 MV 以 DROP TABLE 删除；先删 MV 停止增量写入）→ `DROP TABLE bfe_ai_metrics_1m`。
4. 按仓库 DDL 重建：执行 `bfe_ai_metrics_1m.sql`、`bfe_ai_metrics_1m_mv.sql`。
5. 断言重建后聚合表为空（REPLACE 语义：旧口径数据不随重建保留，等待重算回填）。
6. 构造并执行重算语句：从仓库 `bfe_ai_metrics_1m_mv.sql` 提取 `SELECT ... GROUP BY <全 40 维>` 主体（MV 定义中 `AS` 之后、`;` 之前），前加 `INSERT INTO <库>.bfe_ai_metrics_1m`（对齐设计稿 §4.3 的重算语句，即「同本 MV 的 SELECT」）；等待 1s。
7. 重建后口径断言：与步骤 2 同一套断言逐项通过。

## 预期结果

- 步骤 2 基线断言全部通过。
- 步骤 3–4：DROP + 重建全部成功。
- 步骤 5：重建后（回填前）聚合表行数为 0。
- 步骤 6–7：重算回填后整窗指标与维度分布与重建前完全一致（口径不变）。

## 清理

`t.Cleanup`：`DROP DATABASE <测试库>`；`CLICKHOUSE_IT_KEEP_DB=1` 时保留现场。
