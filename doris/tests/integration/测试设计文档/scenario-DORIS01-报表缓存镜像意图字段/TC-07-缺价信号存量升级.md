# TC-07 缺价信号存量升级（bfe#1479）

## 用例编号与名称

TC07 缺价信号存量升级（`TestTC07PriceMissUpgrade`）

## 所属场景

DORIS01 报表缓存/镜像/意图字段（scenario-DORIS01-report-cache-mirror-intent）

## 版本声明

- `ai-gateway-observability`：`doris/sqls/` 当前资产（明细表 101 列）
- 被测引擎：Doris 3.0.8（WSL2 单机 FE+BE）
- 升级脚本：`doris/sqls/upgrade/2026-10-30-issue-1479-price-miss-columns/bfe_ai_request_log_alter.sql`

## 测试目的

1. 存量表补两列可执行：`ALTER TABLE ... ADD COLUMN` 后 `ai_price_miss`（BOOLEAN，`information_schema` 呈现为 `tinyint`）/ `ai_price_warn`（VARCHAR(32)）就位；
2. 明细层三态语义成立：带信号行读回 `1` / `'subitem_missing'`，旧消息行两列为 **NULL**（不是 0/空串）；
3. 二次执行按预期报错（Doris 3.0.8 不支持 `ADD COLUMN IF NOT EXISTS`，脚本每环境一次）。

## 前置条件

同 TC-01（Doris 可达、具备建库建表权限）。

## 操作步骤

1. 全新安装 schema（`SetupFreshInstall`，不建周期 JOB）。
2. `ALTER TABLE bfe_ai_request_log DROP COLUMN ai_price_miss, DROP COLUMN ai_price_warn` 模拟旧表；断言两列不存在。
3. 执行升级脚本 → 断言两列存在且类型为 `tinyint` / `varchar(32)`。
4. 写入两行：带信号行（`ai_price_miss=1, ai_price_warn='subitem_missing'`）与旧消息行（两列不写 → NULL）。
5. 查询两行并断言取值/NULL。
6. 重复执行升级脚本 → 断言报错信息含 `already exists` 或 `duplicate`。

## 预期结果

- 步骤 3：两列就位且类型正确；
- 步骤 5：带信号行 `1` / `subitem_missing`；旧消息行两列 `NULL`；
- 步骤 6：报 Duplicate column（每环境仅执行一次契约，与 ClickHouse `IF NOT EXISTS` 幂等不同）。

## 与真实导入链路的关系

本用例覆盖 DDL 与明细落库语义；JSON `true/false` → `BOOLEAN` 的**导入链路**验证由 starrocks-it TC02（真实 Kafka → Routine Load）承担，Doris 侧沿用既有约定（doris-it 不生产 Kafka 消息），`COLUMNS` 映射的正确性由 TC02 的 `SHOW CREATE ROUTINE LOAD` 断言覆盖。

测试库由 `common.NewTestDB` 的清理逻辑 `DROP DATABASE` 回收。
