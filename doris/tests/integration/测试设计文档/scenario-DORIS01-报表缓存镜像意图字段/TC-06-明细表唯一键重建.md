# TC-06 明细表唯一键重建（补 logid）

## 用例编号与名称

TC-06 明细表唯一键重建（补请求级判别列 `logid`）

## 所属场景

DORIS01 报表二期（v0.8）Doris 侧对齐缓存/镜像/意图字段

## 版本声明

- `ai-gateway-observability`：当前源码版本（v0.8，#1417 变更）
- `Doris`：本机 WSL2 单机 3.0.8（重建与换名语法以本版本实测为准）

## 测试目的

验证明细表唯一键重建流程（HOWTO §11.4 / 修改说明 §4.2）：

1. **缺陷复现**：旧四列键 `(hostid, log_time, ai_apikey_id, ai_requested_model)` 下，"同秒 + 同 Key + 同模型、仅 `logid` 不同"的并发请求只留 1 行（`log_time` 秒级 + UNIQUE KEY 合并语义）；
2. **修复验证**：执行仓库升级脚本重建后，唯一键含 `logid`，同一批数据各自成行；`logid` 为 NULL 的历史行由 `IFNULL(logid, 0)` 兜底且键约束为 `NOT NULL`；
3. **流程可用**：`_v2` 建表 + 回灌 + `REPLACE WITH TABLE ... PROPERTIES('swap')` 原子换名后新表名立即可读、旧表可删除。

## 运行模式

单组件模式：直连真实 Doris FE，在独立测试库中完整走一遍重建流程（**不依赖 Routine Load / Kafka**——脚本中的 PAUSE/RESUME 为注释形式，仅供存量环境手工执行）。

## 前置条件

1. Doris FE/BE 已启动，root 无密码可连（`SHOW BACKENDS` 中 `Alive: true`）。
2. 同 TC-01（独立随机测试库、`t.Cleanup` 级联清理）。

## 测试数据构造

- **旧 schema 表**：对仓库新 DDL 做逆向替换生成（`UNIQUE KEY(hostid, log_time, ai_apikey_id, ai_requested_model, logid)` → 去掉 `, logid`；`logid BIGINT NOT NULL` → `logid BIGINT`），模拟存量环境。
- **哨兵行 A/B（并发前提）**：同一 `log_time` 秒、同 `hostid='it_host'`、同 `ai_apikey_id='dedup_key'`、同 `ai_requested_model='same-second-model'`，仅 `logid` 不同（1001 / 1002）。
- **哨兵行 C（NULL 兜底）**：另一 4 元组（`ai_apikey_id='null_key'`），`logid` 显式 NULL——历史写入侧缺陷形态。

## 执行步骤

1. 建独立测试库，并按"旧 schema"建明细表。
2. `INSERT` 哨兵行 A、B → 查询 `COUNT(*)`：预期 **1**（旧键覆盖语义，缺陷复现）。
3. `INSERT` 哨兵行 C（`logid` 为 NULL；注意该表 `logid` 为可空值列）→ 查询 `COUNT(*) WHERE ai_apikey_id='null_key'`：预期 1。
4. 执行升级脚本：`sqls/upgrade/2026-10-13-issue-1417-detail-unique-key-logid/bfe_ai_request_log_rebuild.sql`（脚本完成"回灌 + `REPLACE WITH TABLE` 换名"；`_v2` 由测试按新 DDL 表名替换后建好，与 HOWTO §11.5 步骤 5.2 同构）。
5. 校验唯一键：`SHOW CREATE TABLE bfe_ai_request_log` 含五列 `UNIQUE KEY(hostid, log_time, ai_apikey_id, ai_requested_model, logid)`；`information_schema` 中 `logid` 的 `IS_NULLABLE = NO`。
6. 换名后查 `bfe_ai_request_log`：哨兵行 A/B 仍为 **1 行**（**回灌不恢复已丢行**——旧表里这两行早已被合并，历史不可回溯）；哨兵行 C 的 `logid` = **0**（`IFNULL` 兜底）。
7. **重建后重新写入同一批**（同秒 + 同 Key + 同模型、`logid` 1001/1002）→ 查询 `COUNT(*)`：预期 **2**（新键判别力生效，缺陷消除）。
8. `DROP TABLE bfe_ai_request_log_v2`（换名后该名指向旧表），并确认新表名仍可查。

## 预期结果

| 步骤 | 预期 |
|------|------|
| 2 | 1 行（旧四列键下同秒并发被合并，即缺陷） |
| 5 | 五列唯一键；`logid` `Null=No` |
| 6 | A/B 仍 1 行（历史不可回溯，已声明边界）；C 的 `logid = 0`（`IFNULL` 兜底） |
| 7 | **2 行**（重建后同秒并发各自成行，缺陷消除） |
| 8 | 旧表可删除，新表名查询不受影响 |

## 清理

`t.Cleanup`：`DROP DATABASE <测试库> FORCE`（级联删除 `_v2` 等剩余对象）。
