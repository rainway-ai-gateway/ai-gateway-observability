# TC-03 明细到聚合口径

## 用例编号与名称

TC-03 明细到聚合口径

## 所属场景

DORIS01 报表二期（v0.8）Doris 侧对齐缓存/镜像/意图字段

## 版本声明

- `ai-gateway-observability`：当前源码版本（v0.8 二期）
- `Doris`：本机 WSL2 单机 3.0.8

## 测试目的

验证 INSERT JOB 的聚合口径：缓存/镜像/意图新维度按原值聚合；旧版消息（无新字段，NULL）经 `COALESCE` 归一为 `''`/`0`；Token 累计与 demo 样例一致。即设计稿 §4.3/§4.4 的口径断言。

## 运行模式

单组件模式：直连真实 Doris FE。本例**不创建周期 INSERT JOB**（避免每分钟调度写入与手动执行竞争同一分钟桶），改为直接执行仓库 JOB 文件中的 `INSERT..SELECT`（仅 WHERE 窗口替换为固定字面量，SELECT 列映射与 GROUP BY 保持原样）。

## 前置条件

1. Doris FE/BE 已启动，root 无密码可连。
2. `doris/demo/normal_request.json` 存在且含新字段（本例的期望值来源，兼校验 demo 文件与 DDL 一致性）。

## 测试数据构造

- 独立测试库，建明细表/聚合表（不建 JOB）。
- 固定聚合窗口：上一分钟桶 `T0 = DATE_TRUNC(NOW(),'minute') - INTERVAL 1 MINUTE`（字面量，避免跨分钟边界 flaky）。
- 行 A（`T0+20s`，logid=1001）：demo 全字段写入——`ai_cache_status='hit'`、`mirror_hit=1`、`ai_intent_answer='intent-a-1'`、`ai_input/output/total_tokens=34/173/207` 等（值取自 `demo/normal_request.json` 解析结果）。
- 行 B（`T0+40s`，logid=1002）：仅基础列（旧版消息），新字段为 NULL。
- 两行使用桶内不同 `log_time`：明细表 UNIQUE KEY 为 `(hostid, log_time, ai_apikey_id, ai_requested_model)`，同 key 二次写入会覆盖。

## 执行步骤

1. 创建独立测试库并建明细表/聚合表。
2. 解析 demo JSON，按其中新字段取值构造行 A 的 `INSERT`；构造行 B 的最小 `INSERT`。
3. 从仓库 `bfe_ai_metrics_1m_job.sql` 提取 `INSERT..SELECT` 主体，仅将 `WHERE log_time >= ... AND log_time < ...` 替换为 `T0`/`T0+1min` 字面量窗口，`GROUP BY` 及列映射原样保留。
4. 执行该语句。
5. 查询 `bfe_ai_metrics_1m WHERE ts_min = T0`，断言两行：
   - demo 行：`(ai_cache_status, mirror_hit, ai_intent_answer, request_count, input_tokens, output_tokens, total_tokens)` = `('hit','1','intent-a-1','1',34,173,207)`（期望值取自 demo JSON）；
   - 旧消息行：`('', '0', '', '1', '0', '0', '0')`（NULL 归一）。
6. 断言聚合结果恰好 2 行。

## 预期结果

- 上述 6 项断言全部通过（`assertAggRow("demo 行")` / `assertAggRow("旧消息行")` / 行数 = 2）。

## 清理

`t.Cleanup`：`DROP DATABASE <测试库> FORCE`。
