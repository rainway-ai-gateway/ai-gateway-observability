# TC-05 聚合表重建换名

## 用例编号与名称

TC-05 聚合表重建换名

## 所属场景

DORIS01 报表二期（v0.8）Doris 侧对齐缓存/镜像/意图字段

## 版本声明

- `ai-gateway-observability`：当前源码版本（v0.8 二期）
- `Doris`：本机 WSL2 单机 3.0.8（原子换名语法以本版本实测为准）

## 测试目的

验证聚合表重建流程（HOWTO §11.3 / 修改说明 §4.3）：按仓库新 DDL 建 `_v2` 表、写入哨兵数据、原子换名后新表名立即可读且数据不丢。同时固化 Doris 3.0.8 的真实换名语法——设计稿所称 SWAP 在 Doris 3.0.8 中的实际语法为 `ALTER TABLE a REPLACE WITH TABLE b PROPERTIES('swap'='true')`。

## 运行模式

单组件模式：直连真实 Doris FE，在独立测试库中完整走一遍重建换名流程。

## 前置条件

1. Doris FE/BE 已启动，root 无密码可连。
2. 同 TC-01。

## 测试数据构造

- 独立测试库，建明细表/聚合表（新 schema，40 维）。
- `_v2` 表：对仓库 `bfe_ai_metrics_1m.sql` 做表名替换（`CREATE TABLE bfe_ai_metrics_1m` → `CREATE TABLE bfe_ai_metrics_1m_v2`，与 HOWTO §11.3 的 sed 同构）后执行。
- 哨兵行：向 `_v2` 写入一行 `(ts_min=当前分钟, hostid='it_host', ai_apikey_id='swap_key', ai_cache_status='hit', request_count=5, input_tokens=100)`。

## 执行步骤

1. 创建独立测试库并建明细表/聚合表。
2. 按仓库 DDL（表名替换）建 `bfe_ai_metrics_1m_v2`。
3. 向 `_v2` 写入哨兵行。
4. 执行原子换名：`ALTER TABLE bfe_ai_metrics_1m REPLACE WITH TABLE bfe_ai_metrics_1m_v2 PROPERTIES('swap' = 'true')`。
5. 从新表名查询：`SELECT SUM(request_count), SUM(input_tokens) FROM bfe_ai_metrics_1m WHERE ai_apikey_id='swap_key' AND ai_cache_status='hit'`。
6. 删除换名后的旧表（现为 `bfe_ai_metrics_1m_v2`）：`DROP TABLE bfe_ai_metrics_1m_v2`。

## 预期结果

- 换名后从新表名读到哨兵数据：`request_count=5`、`input_tokens=100`。
- 旧表（`_v2`）可正常删除，新表名查询不受影响。

## 清理

`t.Cleanup`：`DROP DATABASE <测试库> FORCE`（级联删除 `_v2` 等剩余对象）。
