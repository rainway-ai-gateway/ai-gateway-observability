# TC-03 明细到聚合口径

## 用例编号与名称

TC-03 明细到聚合口径

## 所属场景

STARROCKS01 StarRocks 对接（报表存储新引擎）

## 版本声明

- `ai-gateway-observability`：当前源码版本（v0.8 StarRocks 对接）
- `StarRocks`：本机 WSL2 单机 3.5.21（FE+BE）

## 测试目的

验证明细表 → 分钟聚合物化视图的口径等价性：异步 MV 周期刷新后，40 维 + 24 指标与 Doris 侧逐列对齐；并验证**增量刷新不重复累计**（跨刷新周期聚合值稳定）。对应设计稿 §4.4 与修改说明 §4.4。

## 运行模式

直插模式：向明细表写入三行样例等价数据（与导入链路解耦，导入正确性由 TC02 保证），轮询等待异步 MV 刷新后断言。StarRocks 不可达时自动 `SKIP`。

## 前置条件

1. StarRocks 已启动，root 无密码可连。
2. `starrocks/sqls/` 资产存在；测试库独立创建。

## 测试步骤

1. 独立测试库中建仓（`bfe_observability.sql`）+ 明细表 + 异步 MV（不建 Routine Load）；
2. 取 2 分钟前的整分钟桶 `tsMin`（避开跨分钟边界 flaky；动态分区 7 天窗口内），写入三行样例等价数据（行 A normal / 行 B rate_limit / 行 C auth_reject，取值与 demo/*.json 一致，落在 `tsMin` 桶的 10s/20s/30s）：
   - 行 B 必须真实写入 `ai_rate_limit_hits`（SR 侧为 VARCHAR，写 JSON 文本字面量）——`rate_limit_hits` 指标由 MV 内 `array_length(CAST(parse_json(ai_rate_limit_hits) AS ARRAY<STRUCT<...>>))` 推导，仅写打平列不足以使指标为 1（本用例首轮失败即此原因，固化为设计约束）；
   - logid 取 Int64 域值（SR 对超界 BIGINT 字面量报 "Number out of range"）；
3. 轮询至 MV 中该桶 `SUM(request_count)=3`（**异步 MV 增量刷新可能分批可见，不能以"出现聚合行"为等待信号**；deadline 240s）；
4. `assertAggregation` 断言：
   - 整窗 9 个关键指标：`request_count=3、error_count=2（rate_limit+auth_reject）、auth_reject_count=1、input/output/total_tokens=95/173/207、rate_limit_hits=1、cache_read/cache_write_tokens=0`（`GROUP BY ts_min + SUM()` 查询范式）；
   - 维度分布：ai_cache_status（hit:1、'':2）、level1（rd:2、'':1）、限流三列（rlp-0002|tpm|tpm1:1、'||':2）、mirror_hit（1:1、0:2）、ai_stream（0:3——直插行未写该列，MV 的 `COALESCE(ai_stream,0)` 归 0 维度，锁定"布尔基列 → tinyint 维度列"的查询契约）、ai_intent_answer（intent-a-1:1、'':2）；
   - 认证拒绝行槽位：`apikey not found|plan_basic|plan_pro|`（slot3 越界为 ''）与 slot1 全桶分布（plan_basic:1、'':2）；
5. **跨刷新周期纪律**：sleep 70s（跨过一个 `REFRESH EVERY 1 MINUTE` 周期）后重跑同一套断言——增量刷新对已聚合分区不得重复累计（对应 CH 侧 at-least-once 重复风险的不同形态）；
6. `t.Cleanup` 删除测试库。

## 预期结果

两套断言全部通过；跨周期重查时整窗指标与维度分布与首次一致（若 `request_count` 变为 6/9 即增量刷新重复累计，断言失败）。

## 备注

- MV 行已是最终聚合值（异步 MV 计算落库），`GROUP BY + SUM()` 仅为聚合查询范式，无 CH 侧 SummingMergeTree 的 merge 兜底问题；
- 与 clickhouse-it TC03 的差异：CH 聚合 MV 随插入**同步**触发（sleep 1s 即可断言），SR 为**周期**刷新（轮询 1-2 分钟）；CH 以 `OPTIMIZE FINAL` 断言排序键纪律，SR 以跨周期重查断言增量刷新纪律。
