# TC-06 缺价信号存量升级（bfe#1479）

## 用例编号与名称

TC06 缺价信号存量升级（`TestTC06PriceMissUpgrade`）

## 所属场景

STARROCKS01 StarRocks 对接（scenario-STARROCKS01-starrocks-dock）

## 版本声明

- `ai-gateway-observability`：`starrocks/sqls/` 当前资产（明细表 104 列）
- 被测引擎：StarRocks 3.5.21（WSL2 单机 FE+BE）
- 升级语句取自 `starrocks/docs/modifications/2026-10-30-issue-1479-price-miss-columns/design-changes.md` §4（SR 3.5 不支持 `ADD COLUMN IF NOT EXISTS`，故不提供独立升级 SQL 文件）

## 测试目的

1. 存量表补两列可执行，且类型正确（`DESC` 口径）：`ai_price_miss` 必须是 `boolean`（JSON 布尔落 `TINYINT` 会静默写 NULL，issue #10 的教训），`ai_price_warn` 为 `varchar(32)`；
2. 明细三态语义成立：带信号行读回 `1` / `'subitem_missing'`，旧消息行两列 **NULL**（不是 0/空串）；
3. SR Schema Change 是异步的：列的出现/消失都要轮询 `information_schema` 直到可见/不可见。

## 前置条件

同 TC-01（StarRocks 可达）；本用例不需要 Kafka。

## 操作步骤

1. 全新安装 schema（明细表 + 聚合 MV，不建 Routine Load）。
2. `ALTER TABLE bfe_ai_request_log DROP COLUMN ai_price_miss, DROP COLUMN ai_price_warn` 模拟旧表 → 轮询直到两列不可见。
3. 按设计稿 §4 的语句 `ADD COLUMN ai_price_miss BOOLEAN ... AFTER ai_intent_questions_version, ADD COLUMN ai_price_warn VARCHAR(32) ... AFTER ai_price_miss` → 轮询直到两列可见。
4. `DESC` 查询断言两列类型。
5. 写入两行（带信号行 `1`/`subitem_missing`；旧消息行两列 NULL），查询断言取值/NULL（SR 的 `IF(NULL, ...)` 会塌成 false，故查询用 `IF(col IS NULL, ...)` 显式判空）。

## 预期结果

- 步骤 4：`ai_price_miss` = `boolean`、`ai_price_warn` = `varchar(32)`；
- 步骤 5：带信号行 `1` / `subitem_missing`；旧消息行两列 `NULL`；
- 全程无 Schema Change 失败（重复 ADD 会报 `Duplicate column name`，属预期，由 TC04 的 `ADD COLUMN IF NOT EXISTS` 负向断言间接覆盖）。

## 清理

测试库由 `common.NewTestDB` 的清理逻辑 `DROP DATABASE FORCE` 回收。
