# 场景 STARROCKS01：StarRocks 对接（报表存储新引擎）

## 1. 场景说明

**被测对象**：`ai-gateway-observability/starrocks/sqls/` 下的四份真实 SQL 资产（不做副本，仅做与 `setup.sh` 一致的 `${VAR}` 变量替换）：建库 `bfe_observability.sql`、明细表 `bfe_ai_request_log.sql`、分钟聚合物化视图 `bfe_ai_metrics_1m.sql`、Routine Load `bfe_ai_log_load_routine.sql`。

**背景**：v0.8 在 Doris 链路之外新增 StarRocks 报表存储引擎（修改说明见 `starrocks/docs/modifications/2026-10-02-starrocks-dock/design-changes.md`）。StarRocks 具备 Routine Load（与 Doris 语法同构），但无 Doris 式 `CREATE JOB`，分钟聚合改用异步物化视图：

| Doris 机制 | StarRocks 等价物（本场景被测对象） |
|------------|--------------------------------------|
| Routine Load（Kafka 消费 + COLUMNS 映射打平） | 同构 Routine Load `bfe_ai_log_load`（level/限流打平用 `get_json_string` 按 JSON 路径取值 + UTC 墙钟算术式在 COLUMNS 内完成，明细见 TABLE_DESIGN §2.3） |
| `CREATE JOB ... ON SCHEDULE EVERY 1 MINUTE` 分钟聚合 INSERT SELECT | 异步物化视图 `bfe_ai_metrics_1m`（`REFRESH ASYNC EVERY (INTERVAL 1 MINUTE)`，分区列 `ts_day` + `partition_ttl=7 DAY`，MV 名即表契约名） |
| `UNIQUE KEY` 明细表 | `DUPLICATE KEY` 明细表（排序键四列一致，append-only 无更新语义） |
| 动态分区 7 天保留 | 明细表动态分区 `start=-7`；MV `partition_ttl=7 DAY` |

**测试环境**：本机 WSL2 单机 StarRocks 3.5.21（FE+BE，`starrocks-installation.md`，MySQL 协议 `127.0.0.1:9030`，root 无密码），Go 测试经 go-sql-driver/mysql 直连；TC02 另需本机 WSL2 KRaft 单节点 Kafka 4.3.1（`kafka-installation.md`，`127.0.0.1:9092`）。每个用例使用独立测试库（基名 `bfe_observability_test` 衍生 `_it_<用例>_<纳秒后缀>`，结束后 `DROP DATABASE FORCE` 清理）。StarRocks 未启动时全部用例自动 `SKIP`；Kafka 未启动时 TC02 单独 `SKIP`。

**目录与运行**：

```bash
cd ai-gateway-observability/starrocks/tests/integration
go test ./... -v                                   # 全部
go test ./implementation/scenario-STARROCKS01-starrocks-dock/ -run TestTC01 -v   # 单例
```

## 3. 关键设计取舍

- **真实 Kafka 链路**：StarRocks 侧的打平发生在 Routine Load 的 COLUMNS 映射路径上（等价 Doris），TC02 必须用真实生产 → Routine Load 链路验证；Kafka 不可达时 TC02 单独 Skip。
- **demo 样例的消息层改写（不改 demo 文件）**：① `timestamp` 重写为当前时刻——demo 时间戳 2026-08-24 早于动态分区 `start=-7` 的既有分区范围，不重写会成为"无对应分区"错误行（与 CH 侧 TTL 丢弃同理不同机制）；② `logid` 重写到 Int64 域——**SR 对超界 BIGINT 直接拒绝**（INSERT 字面量报 "Number out of range"；Routine Load 计错误行跳过），Doris 静默截断存储、CH UInt64 原值保留，三引擎差异点在本场景固化（`demoCases` 按"保持数字形态"原则收敛：10602749765076101032→1060274976507610103、12345678901234567890→1234567890123456789）；③ 多行 JSON 压缩单行（等价 log-reader 产出）。
- **异步 MV 的测试节奏**：SR 无 CH 侧"插入同步触发"，聚合断言改为轮询（deadline 240s）等待 MV 周期刷新；TC03 额外跨一个刷新周期（70s）重查，断言**增量刷新不重复累计**（对应 CH 侧 at-least-once 重复风险的不同形态）；TC05 利用"异步 MV 创建即全量回填"特性，重建后无需手工重算，轮询至口径恢复即可。
- **RL PAUSED 自愈**：本机 9p 盘上 Kafka 元数据获取偶发失败会使 Routine Load 创建即 PAUSED，测试轮询期间检测 SHOW ALL ROUTINE LOAD 并自动 RESUME（幂等）。
- **测试 topic 只建不删**：本机 Kafka 数据目录在 /mnt/d（WSL 9p），删除 topic 时 broker 对分区目录的 rename（`*.stray`）会 AccessDenied，导致 log dir failed 并使 broker 宕机；topic 命名唯一、仅 3 条消息，直接保留。
- **TC03/TC04/TC05 直插明细**：与 doris-it / clickhouse-it 同款方式，聚合口径与导入链路解耦验证（导入正确性由 TC02 保证）；插入列清单只含标量列，复杂 ARRAY<STRUCT> 列（路由规则/限流命中/配额计划数组本体）不参与聚合口径断言，留给 TC02 真实消费路径验证——规避 SR 结构体字面量与 VALUES 推断的组合风险；logid 取 Int64 域值（见上条）。
- **重复应用行为固化**：与 clickhouse-it 的 `IF NOT EXISTS` 幂等不同，starrocks 资产沿 doris 语义（同名重建报错）——TC01 将三类对象的报错信息（表/MV "already exists"、RL "Name ... already used in db"）固化为断言，防止误改 SQL 引入 IF NOT EXISTS 造成"重复 setup 静默跳过"的运维错觉。
- **go driver 与 mysql CLI 的执行通道差异**：starrocks 资产的 `--skip-comments` 问题（FE 拒绝仅含注释的语句）只影响 mysql CLI；go-sql-driver 整包发送（COM_QUERY 服务端切分），harness 无需处理注释。
- **集成测试驱动出的方言知识**（已固化为断言/文档）：
  1. **Routine Load 表达式在 BE 任务创建/运行时才分析**——CREATE 成功不代表表达式兼容；初版 json_extract 平移在冒烟（仅任务创建）阶段未暴露，由 TC02 真实消费链路抓出（PAUSED→RESUME 循环、任务报 no matching function）。
  2. SR 3.5.21 的 JSON 函数面：`json_extract` 无 `(varchar, varchar)` / `(json, varchar)` 签名；`get_json_string(varchar, path)` 为 varchar JSON 文本的取值函数（返回去引号字符串，等价 Doris `json_unquote(json_extract(...))`）；`parse_json` + `CAST(... AS ARRAY<STRUCT<...>>)` 可在查询侧还原嵌套结构。
  3. **嵌套列以 VARCHAR(JSON 文本) 落地**：VARCHAR 不能直转 ARRAY<STRUCT>（Not support cast）、派生列禁止自引用（can't be found in column list）、非表列派生名被拒（Mapping column is not in table）——三备选全灭后的决策，列名契约不变。
  4. **超界 BIGINT 被拒绝**（INSERT 报 Number out of range；Routine Load 计错误行跳过），demo 样例 logid 重写到 Int64 域；与 Doris 静默截断、CH UInt64 原值保留为三引擎差异点。
  5. 异步 MV 增量刷新分批可见：轮询等待必须以"聚合行数到位"（SUM(request_count)=N）为信号，不能以"出现聚合行"为信号。
  6. `ADD COLUMN IF NOT EXISTS` 不支持（升级脚本幂等写法与 Doris 3.0 / CH 不同，须 information_schema 判断或容忍报错）。
  7. `UNIX_TIMESTAMP(datetime)` 按会话时区解释 UTC 墙钟列（差 8h）；断言 epoch 用 `TIMESTAMPDIFF(SECOND, '1970-01-01', log_time)` 墙钟算术。
  8. BOOLEAN 在 information_schema.columns 以 `tinyint` 呈现；SR 无 `array_size`（等价函数 `array_length`）。
